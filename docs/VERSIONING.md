# Versioning checklist

All packages use [semver](https://semver.org/). The mobile app's `app.json` is the source of truth — Expo prebuild propagates its values to native projects.

## Semver bump (marketing version)

Update these files when changing the version number (e.g. `0.1.0` → `0.2.0`):

- [ ] `mobile/app.json` — `expo.version`
- [ ] `mobile/package.json` — `version`
- [ ] `backend/package.json` — `version`

## Build number bump (every store upload)

Increment these for each App Store / Play Store upload, even if the marketing version hasn't changed:

- [ ] `mobile/app.json` — `expo.ios.buildNumber` (string, must increase)
- [ ] `mobile/app.json` — `expo.android.versionCode` (integer, must increase)

## Commit convention

```
chore: bump version to X.Y.Z
```

## Notes

- `mobile/ios/` is gitignored. Native version fields (`CFBundleShortVersionString`, `MARKETING_VERSION`, `CFBundleVersion`, `CURRENT_PROJECT_VERSION`) are regenerated by `expo prebuild` from `app.json`.
- Build numbers only matter when uploading to App Store Connect / Google Play Console. Until then they are no-ops.
- If backend versioning diverges from mobile in the future, bump them independently.
